# `bucket.list_blobs(prefix=prefix)`

আচ্ছা, এই line-টা নিয়ে আটকে যাওয়াটা একদম স্বাভাবিক। তাড়াহুড়ো নেই — পাশে বসে ভেঙে ভেঙে দেখি।

এই এক line-টাকেই ভেঙে ভেঙে দেখি। এখানে আসলে তিনটা আলাদা ধারণা একসাথে জড়ো হয়েছে, তাই একবারে দেখলে ঘোলাটে লাগে। একটা বুঝে তারপর পরেরটায় যাব।

```python
bucket.list_blobs(prefix=prefix)
```

## প্রথমে সবচেয়ে জরুরি কথাটা — GCS-এ কোনো folder নেই

এটাই আসল ধাঁধা, আর এখানে চোখ ধোঁকা খায়। দোষ তোমার না। তুমি GCS Console খুললে এমন দেখো:

```text
📁 hr_policies/
   📁 raw/
      📄 work_from_home_policy.txt
      📄 travel_expense_policy.txt
```

দেখে মনে হয় folder-এর ভেতরে folder। কিন্তু এটা মিথ্যা। Console তোমাকে সান্ত্বনা দিচ্ছে মাত্র — চোখ যাতে শান্ত থাকে, সেজন্য `/` দেখে folder এঁকে দেখায়।

আসলে bucket-এর ভেতরে আছে শুধু একটা লম্বা flat তালিকা, যেখানে প্রতিটা file-এর নাম একটা পুরো string:

```text
hr_policies/raw/work_from_home_policy.txt
hr_policies/raw/travel_expense_policy.txt
hr_policies/processed/work_from_home_policy.json
noise_policies/raw/canteen_menu.txt
```

এখানে `/` কোনো বিশেষ character নয় — নামের অংশমাত্র, ঠিক যেমন `_` বা `.`। তোমার computer-এর folder আর GCS-এর এই ব্যাপারটা একদম আলাদা।

একটা তুলনা দেই, তাহলে গায়ে সেঁটে যাবে। তোমার laptop-এ folder সত্যিকারের জিনিস — খালি folder বানিয়ে রাখা যায়। GCS-এ তা যায় না, কারণ folder বলে কিছু নেই। file-ই শুধু আছে, আর তাদের নামে slash আছে।

## তাহলে prefix কী

যেহেতু সব নাম একটা লম্বা string, তাই "folder-এ ঢোকা" সম্ভব নয়। বদলে GCS যা দেয় তা হলো: **এই অক্ষরগুলো দিয়ে শুরু হওয়া সব নাম আমাকে দাও।**

এটাই prefix। মানে নামের শুরুর অংশ। শুনতে ছোট, কিন্তু এই line-এর পুরো মানে এখানেই।

```python
bucket.list_blobs(prefix="hr_policies/raw/")
```

GCS ভেতরে ভেতরে করছে এটাই:

```python
# কাল্পনিক — GCS server যা করছে তার সরল রূপ
for name in all_names_in_bucket:
    if name.startswith("hr_policies/raw/"):
        yield name
```

চিনতে পারছ? এটা `startswith` — ঠিক যেটা তুমি `extract_policy_category`-তে ব্যবহার করেছিলে। একই ধারণা, শুধু এবার GCS server-এ চলছে। তুমি এটা আগেই জানো, শুধু জায়গাটা বদলেছে।

দেখে নাও কোনটা মেলে, কোনটা মেলে না:

| Blob-এর নাম | `prefix="hr_policies/raw/"` |
|---|---|
| `hr_policies/raw/wfh.txt` | মেলে |
| `hr_policies/raw/travel.txt` | মেলে |
| `hr_policies/raw/2024/old.txt` | মেলে — subfolder-ও ভেতরে পড়ে |
| `hr_policies/processed/wfh.json` | মেলে না — `processed` আর `raw` এক নয় |
| `noise_policies/raw/menu.txt` | মেলে না — শুরুটাই আলাদা |

তৃতীয় row-টা বিশেষভাবে খেয়াল করো। Prefix "এক স্তর নিচে" থামে না — শুরুটা মিললেই যথেষ্ট, যত গভীরেই থাকুক। এটা মনে না রাখলে পরে অবাক হবে। `2024/old.txt` ওই prefix-এর "ভেতরে" বলে বাদ যায় না। শুরু মিলেছে, তাই সেও আসবে।

## `prefix=prefix` — এই দুইটা এক জিনিস নয়

এখানে এক সেকেন্ড থামো। এই জায়গাটায় বেশিরভাগ মানুষ আটকায়, আমিও প্রথমবার আটকেছিলাম, কারণ দুই পাশে একই শব্দ:

```python
bucket.list_blobs(prefix=prefix)
#                    ↑       ↑
#                    │       └── তোমার variable, যেখানে মান আছে
#                    └────────── Google-এর parameter-এর নাম
```

বাম পাশেরটা হলো keyword argument-এর নাম — Google-এর library এই নামে জিনিসটা চায়, তুমি বদলাতে পারবে না।

ডান পাশেরটা তোমার নিজের variable, যেটা loop থেকে আসছে।

নাম দুইটা মিলে গেছে কাকতালীয়ভাবে নয় — পাঠযোগ্যতার জন্য ইচ্ছে করেই মেলানো। চাইলে variable-এর নাম অন্য রাখতে পারতে, তাতে line-টা এমন দেখাত:

```python
for p in prefixes:
    bucket.list_blobs(prefix=p)      # হুবহু একই কাজ
```

মানটা যা বসছে। বাইরের loop-এর প্রথম চক্করে একটা, দ্বিতীয় চক্করে আরেকটা:

```python
bucket.list_blobs(prefix="hr_policies/processed/")     # ১ম চক্করে
bucket.list_blobs(prefix="noise_policies/processed/")  # ২য় চক্করে
```

## `bucket.list_blobs()` কী ফেরত দেয়

এটা list নয় — **iterator**। পার্থক্যটা notebook-এ কামড় দেবে, তাই এখনই জেনে রাখো। পরে খালি ফল দেখে ঘণ্টা খোঁজার দরকার নেই।

```python
blobs = bucket.list_blobs(prefix="hr_policies/raw/")

print(blobs)         # <google.api_core.page_iterator.HTTPIterator object at 0x...>
print(len(blobs))    # TypeError — iterator-এর len নেই
```

Iterator মানে "চাহিদামতো একটা একটা করে দেব" — আগে থেকে সব এনে রাখে না। ভেতরে ভেতরে সে page ধরে (default ১০০০টা করে) API call করতে থাকে যখন loop ঘোরে।

এর সবচেয়ে বিপজ্জনক দিক — একবার ঘুরলেই শেষ:

```python
blobs = bucket.list_blobs(prefix="hr_policies/raw/")
print(list(blobs))   # ['wfh.txt', 'travel.txt', ...]
print(list(blobs))   # []  ← খালি! নিঃশেষ হয়ে গেছে
```

Notebook-এ বারবার দরকার হলে একবারেই list বানিয়ে রাখো:

```python
blobs = list(bucket.list_blobs(prefix="hr_policies/raw/"))
```

তোমার code-এ সমস্যা নেই, কারণ `for` loop একবারই ঘোরে। সেই একবারেই কাজ হয়ে যায়।

## Loop-এর ভেতরে `blob` জিনিসটা কী

প্রতিটা iteration-এ `blob` একটা object, file নিজে নয় — বরং file সম্পর্কে তথ্য। file-এর ভেতরের লেখা এখনও হাতে আসেনি।

```python
for blob in bucket.list_blobs(prefix="hr_policies/raw/"):
    print(blob.name)    # 'hr_policies/raw/work_from_home_policy.txt'
    print(blob.size)    # 2847  (bytes)
```

এখানে একটা কথা খুব জরুরি: `list_blobs` file-এর ভেতরের content আনে না। সে শুধু নাম আর metadata আনে।

Content আসে তখনই, যখন তুমি আলাদা করে বলো:

```python
text = blob.download_as_text()    # এইটা আসল download, আলাদা API call
```

এই ভাগটা তোমার code-এ কাজে লেগেছে। মনে করো:

```python
for blob in bucket.list_blobs(prefix=prefix):
    if not blob.name.endswith(".json"):
        continue                          # নাম দেখেই বাদ, download হয়নি
    record = json.loads(blob.download_as_text())   # শুধু যোগ্যগুলো নামে
```

`.pdf` file-টার নাম দেখেই বাদ দেওয়া হলো, তার ১০ MB কখনো নামলই না। ফিল্টার-টা loop-এর একদম শুরুতে রাখার এটাই লাভ। আগে নাম দেখো, পরে দরকার হলেই নামাও।

### `blob.name`-এ পুরো path থাকে, শুধু filename নয়

এটাও একটা সাধারণ বিভ্রান্তি। Prefix দিয়ে খুঁজলেও নাম থেকে ওই অংশ কেটে যায় না।

```python
bucket.list_blobs(prefix="hr_policies/raw/")
# blob.name → 'hr_policies/raw/work_from_home_policy.txt'
#             └────────────────┘
#             prefix-টা কাটা যায় না, নামের ভেতরেই থাকে
```

Prefix দিয়ে ফিল্টার করেছ বলে সে অংশটা নাম থেকে উধাও হয় না। এই কারণেই আগের function-এ আলাদা করে filename বের করতে হয়েছিল:

```python
filename = blob.name.rsplit("/", 1)[-1]    # 'work_from_home_policy.txt'
```

## Notebook-এ নিজে দেখে নাও

পড়ার চেয়ে চোখে দেখলে অনেক পরিষ্কার হবে। নিচের তিনটা একে একে চালাও। প্রথমটা পুরো তালিকা, তারপর আস্তে আস্তে ছোট করে।

এটা চালাও:

```python
from google.cloud import storage
from myhr_rag import config

client = storage.Client(project=config.PROJECT_ID)
bucket = client.bucket(config.GCS_BUCKET_NAME)

# prefix ছাড়া — পুরো bucket, flat তালিকাটা নিজের চোখে দেখো
print("=== সব blob ===")
for blob in bucket.list_blobs():
    print(" ", blob.name)
```

Output দেখবে এরকম — folder-এর কোনো চিহ্ন নেই, শুধু লম্বা নাম:

```text
  hr_policies/raw/work_from_home_policy.txt
  hr_policies/raw/travel_expense_policy.txt
  hr_policies/processed/work_from_home_policy.json
  noise_policies/raw/canteen_menu.txt
```

এবার prefix দিয়ে সংকুচিত করো:

```python
print("=== শুধু raw zone ===")
for blob in bucket.list_blobs(prefix="hr_policies/raw/"):
    print(" ", blob.name)
```

তারপর ইচ্ছে করে অদ্ভুত একটা prefix দাও, যেটা folder-এর সীমানা মানে না:

```python
print("=== prefix='hr' ===")
for blob in bucket.list_blobs(prefix="hr"):
    print(" ", blob.name)
```

এটা `hr_policies/` এর সবকিছু আনবে — raw, processed সব। কারণ prefix folder চেনে না, শুধু অক্ষর মেলায়। এই একটা পরীক্ষা করলেই ব্যাপারটা হাড়ে হাড়ে বুঝে যাবে। `hr` দিয়ে যা শুরু, সব চলে আসবে। Folder-এর দরজা এখানে নেই।

## দুইটা ফাঁদ, যেগুলো তোমাকে কামড়াতে পারে

দুইটাই চুপচাপ ভুল করে। Error আসে না, তাই ধরা পড়ে দেরিতে। জেনে রাখলে সেই ঘণ্টাখানেক বাঁচবে।

শেষের slash বাদ পড়লে:

```python
prefix = "hr_policies/raw"     # slash নেই
```

এটা `hr_policies/raw/` এর পাশাপাশি `hr_policies/raw_backup/` আর `hr_policies/raw_old_2023/`-ও টেনে আনবে, কারণ তিনটারই শুরু `hr_policies/raw`। সবসময় `/` দিয়ে শেষ করো।

শুরুতে slash দিলে:

```python
prefix = "/hr_policies/raw/"   # শুরুতে slash
```

শূন্য ফল আসবে। কারণ কোনো blob-এর নামই `/` দিয়ে শুরু হয় না — Linux path-এর অভ্যাসে এই ভুলটা সহজেই হয়। laptop-এ path লেখার অভ্যাস এখানে এসে লেগে যায়, আর GCS চুপ করে খালি তালিকা দেয়।

দুই ক্ষেত্রেই GCS কোনো error দেবে না। চুপচাপ খালি বা ভুল তালিকা দেবে, আর তুমি পরে vector store ঘেঁটে ভাববে "document গেল কোথায়"। এজন্যই সেই অভ্যাসটা —

```python
docs = load_processed_documents_from_gcs()
print(f"loaded {len(docs)} documents")
```

`0` দেখলে সন্দেহের প্রথম জায়গা হবে prefix। ওখান থেকেই খোঁজা শুরু করো।

## এক বাক্যে

হাতে রেখে দিই, যাতে পরে এই পাতায় ফিরতে না হয়।

`bucket.list_blobs(prefix=prefix)` মানে — **এই bucket-এ যত file আছে, তাদের মধ্যে যাদের নাম এই অক্ষরগুলো দিয়ে শুরু, তাদের নাম আর তথ্য একটা একটা করে দাও (content নয়)।**

## `blobs`-এর data type কী

ভালো প্রশ্ন, কারণ এখানেই বেশিরভাগ মানুষ ধরে নেয় "list হবে নিশ্চয়ই" — আর সেটাই notebook-এ কামড় দেয়। ধরে নেওয়াটা স্বাভাবিক। `for` loop-এ list আর iterator একই রকম দেখায়।

উত্তর: `list_blobs()` ফেরত দেয় একটা `HTTPIterator` object। পুরো নাম `google.api_core.page_iterator.HTTPIterator`। আর তার ভেতরে ঘোরার সময় প্রতিটা `blob` হলো একটা `google.cloud.storage.blob.Blob` object।

মানে দুই স্তরে দুইটা type:

```python
blobs = bucket.list_blobs(prefix=prefix)   # HTTPIterator
for blob in blobs:                          # প্রতিটা blob → Blob object
    ...
```

নিজে যাচাই করে নাও। চোখে দেখলে নাম দুটো আর গুলিয়ে যাবে না:

```python
blobs = bucket.list_blobs(prefix=config.GCS_PREFIX)
print(type(blobs))
# <class 'google.api_core.page_iterator.HTTPIterator'>

for blob in blobs:
    print(type(blob))
    break
# <class 'google.cloud.storage.blob.Blob'>
```

### Iterator মানে কী, আর এতে কী বদলায়

`HTTPIterator` list নয়, যদিও `for` loop-এ দুইটাকে একই রকম দেখায়। পার্থক্যটা হলো — list-এ সব জিনিস আগে থেকে memory-তে বসানো থাকে, iterator-এ থাকে না। সে "চাইলে পরেরটা দেব" ভঙ্গিতে অপেক্ষা করে।

নামের `HTTP` অংশটা ইঙ্গিত দিচ্ছে আসল ব্যাপারটা: এর ভেতরে একটা network connection লুকানো আছে। Loop যখন ঘোরে, সে পর্দার আড়ালে GCS API-তে request পাঠায়, ১০০০টা করে নাম নিয়ে আসে (এক page), সেগুলো শেষ হলে আবার পরের page চায়। তুমি টেরও পাও না। সেটাই সুবিধা — তোমাকে page জোড়া লাগাতে হয় না।

এই কারণেই তিনটা জিনিস list-এর মতো কাজ করে না:

```python
blobs = bucket.list_blobs(prefix="hr_policies/raw/")

len(blobs)      # TypeError: object of type 'HTTPIterator' has no len()
blobs[0]        # TypeError: 'HTTPIterator' object is not subscriptable
blobs[1:3]      # একই সমস্যা
```

কেন? কারণ `len()` জানতে হলে সবকিছু গুনে ফেলতে হবে, আর `[0]` জানতে হলে অন্তত প্রথমটা এনে রাখতে হবে। Iterator এসব আগে থেকে করে রাখেনি — করতে গেলে সব page ডাউনলোড করতে হতো, যেটা এড়ানোই তার উদ্দেশ্য। Error দেখে ঘাবড়াবে না। iterator-এর স্বভাব এটাই।

### সবচেয়ে বিপজ্জনক দিক — একবার ঘুরলেই নিঃশেষ

এটা মনে রাখা জরুরি। Notebook-এ দ্বিতীয়বার খালি ফল দেখলে মনে হবে data উধাও। data আছে, iterator শেষ হয়ে গেছে।

```python
blobs = bucket.list_blobs(prefix="hr_policies/raw/")

print(len(list(blobs)))   # 3
print(len(list(blobs)))   # 0   ← খালি!
```

দ্বিতীয়বার শূন্য কেন? কারণ iterator-এর ভেতরে একটা অদৃশ্য কাঁটা (cursor) আছে যেটা এগোতেই থাকে, পেছনে ফেরে না। একবার শেষ প্রান্তে পৌঁছে গেলে সে "আর কিছু নেই" বলতে থাকে।

List-এর সাথে তুলনা করো। একই জিনিস বারবার চাইলে list শান্ত থাকে:

```python
names = ["a", "b", "c"]
print(list(names))   # ['a', 'b', 'c']
print(list(names))   # ['a', 'b', 'c']   ← যতবার খুশি
```

Notebook-এ এই ফাঁদটায় পড়বেই, কারণ সেখানে স্বাভাবিকভাবেই এক জিনিস বারবার দেখতে ইচ্ছে করে। সমাধান — একবারেই list বানিয়ে রাখো:

```python
blobs = list(bucket.list_blobs(prefix="hr_policies/raw/"))   # এখন সত্যিকারের list

len(blobs)       # 3
blobs[0].name    # কাজ করে
# for b in blobs: যতবার খুশি
```

এতে সব নাম একসাথে memory-তে চলে আসে — যা কয়েকশো file-এ কোনো সমস্যাই নয় (শুধু নাম আর metadata, content নয়)।

### তোমার code-এ সমস্যা নেই কেন

```python
for blob in bucket.list_blobs(prefix=prefix):
```

এখানে iterator-টা কোনো variable-এ রাখাই হয়নি — সরাসরি `for`-এ ঢুকে গেছে, একবার ঘুরেছে, কাজ শেষ। পুনর্ব্যবহারের প্রশ্নই আসে না। তাই production-এর এই লাইন নিয়ে দুশ্চিন্তা কোরো না।

উল্টো দিকে, iterator ব্যবহার করাটা এখানে সুবিধা। ১০,০০০ file থাকলেও সব নাম একসাথে RAM-এ জমে না; loop যত এগোয়, তত টুকরো টুকরো আসে।

### `blob` object-টা কী ধরে রাখে

প্রতিটা `Blob` object-এ থাকে file সম্পর্কে তথ্য, file-এর ভেতরের লেখা নয়। নামগুলো চোখের সামনে রাখো:

```python
blob.name           # 'hr_policies/raw/wfh.txt'   → str
blob.size           # 2847                         → int (bytes)
blob.content_type   # 'text/plain'                 → str
blob.updated        # datetime object
blob.bucket         # Bucket object
```

Content পেতে আলাদা করে চাইতে হয়:

```python
blob.download_as_text()    # → str
blob.download_as_bytes()   # → bytes
```

এই দুইটা method-ই আসল download API call। তোমার code-এ `blob.name.endswith(".json")` দিয়ে যে ফিল্টার আছে, সেটা কাজ করে শুধু নাম দেখে — অর্থাৎ অযোগ্য file-গুলোর একটা বাইটও কখনো নামে না।

### এক নজরে

পরে ফিরে দেখলে এই ছকটাই যথেষ্ট।

| জিনিস | Type | চরিত্র |
|---|---|---|
| `bucket.list_blobs(...)` | `HTTPIterator` | lazy, একবার ঘোরে, `len()` / index নেই |
| `list(bucket.list_blobs(...))` | `list` | সব memory-তে, বারবার ব্যবহারযোগ্য |
| loop-এর ভেতরের `blob` | `Blob` | metadata ধরে, content নয় |
| `blob.name` | `str` | পুরো path সহ নাম |
| `blob.download_as_text()` | `str` | এখানেই আসল content আসে |

একটা সহজ নিয়ম করে নাও: production code-এ iterator-ই থাক (memory বাঁচে), কিন্তু notebook-এ ঘাঁটাঘাঁটির সময় `list()` দিয়ে মুড়ে নাও — নইলে দ্বিতীয় cell চালিয়ে খালি ফল দেখে বিভ্রান্ত হবে।
